# Acceptance scenarios and evidence

These are executable acceptance tests for the implemented laboratory. Each run must emit a run ID, source commit, versions, preconditions, actions, UTC timestamps, assertions, redacted evidence references, result, and limitations. A result applies only to its recorded environment and source state. A skipped dependency produces SKIPPED with a reason, never PASS. Unit tests or mocks cannot replace the real service checks required below.

## Evidence package

Produce evidence/<run_id>/manifest.json, events.jsonl, assertions.json, and report.md. The manifest records the source revision and snapshot, platform, execution window, and per-scenario result. Assertions link to redacted events. Sensitive fixtures are not included.

Report measured time to assignment, verified containment, and healthy recovery for each applicable scenario. State where exposure time is known because the lab injected it. Do not describe those synthetic timings as production response capability or a product benchmark.

Include a trace from each requirement to implementation files and at least one test or documented inspection. Missing requirements must be listed explicitly. The core can be declared complete only when A01–A26 pass on at least one declared platform, with any additional supported-platform claims backed by their own runs.

## Review rubric

The lab should make it possible to follow one service from approved intake to issued access, an exposure or identity event, an owner decision, effective containment, and recovery. The same records must agree across UI, issuer, target, and evidence export. A green dashboard unsupported by target behavior fails the demonstration.
